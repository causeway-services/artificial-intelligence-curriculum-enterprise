# Multi-Agent Operating Discipline for Teams

**Run several AI coding agents without losing ownership of the work.**

One agent can be a useful assistant. Two agents sharing work become an operations problem: they can overwrite each other's changes, declare success without evidence, repeat completed tasks, or leave a session that no one knows how to recover.

This live, practice-first Causeway Services course teaches the operating habits that address those failures. You bring a real engineering task; you leave with written procedures your own team can use.

## Who this course serves

Engineering leads, solo technical founders, and developers who already use Claude Code, Codex, or comparable agentic coding tools and want to coordinate two or more sessions. You should be comfortable working in a software repository and interpreting basic test or build results. No particular agent framework is required.

## Five sessions. Five working artifacts.

1. **The complete brief — 90 minutes.** Turn a real backlog item into a bounded commission with ownership, paths, permissions, exclusions and a checkable completion condition. Deliverable: a reusable dispatch brief.
2. **When *not* to fan out — 90 minutes.** Compare parallel and sequential execution on the same task; identify when additional agents increase collision and review costs. Deliverable: a fan-out decision checklist.
3. **Steering and recovering — 90 minutes.** Practice intervening in a running task and resuming an interrupted task without quietly creating two writers. Deliverable: an interruption and recovery runbook.
4. **Receipts as working memory — 90 minutes.** Replace vague claims of completion and unreadable transcripts with dated records of what actually changed and how it was checked. Deliverable: a receipt convention.
5. **Collision to coordination — 120 minutes.** Work through a documented 561 Group concurrent-session failure and practice dividing file custody through direct messages and path manifests. Deliverable: a coordination protocol for shared work.

Sessions include exercises and review of participant work. The course is about operating discipline, not promises that every agent output will be correct or that adding agents always makes work faster.
